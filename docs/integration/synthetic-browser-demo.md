# Local synthetic browser demonstration

This is an experimental deterministic C1 demonstration, not autonomous AI or production authentication. It accepts only byte-identical `ledger.csv`, `bank_statement.xlsx`, or `edge_cases.csv` from `public/samples/ingestion`. The server chooses fixed conventions for these known synthetic files, runs the stable ingestion engine, checks its C1 projection, and atomically stores the full trusted result and synthetic ownership in a disposable in-memory PGlite database. No V2 record is cast to C1. All database contents disappear on server restart.

Start a local development server **bound to 127.0.0.1 only** with `FINGENCE_AI_LOCAL=1`, `FINGENCE_V2_I1_LOCAL=1`, and an independently chosen 64-character lowercase hexadecimal `FINGENCE_V2_I1_TOKEN` in the process environment. Enter that local capability in the page; it is not a real user session. Do not save it in Git or browser storage. Open `/ai-ingestion/synthetic-financial`. Select one approved file and process it. The server derives the synthetic tenant from the capability; clients cannot supply a tenant, financial values or verification decisions. The processing operation ID is stored in browser storage solely for uncertain-response investigation. A restart loses both the operation registry and the temporary database; an unknown operation stays unresolved and is never automatically retried.

Select a processed batch. Its counts and accepted source rows come from the database. The exact source-signed sum includes VALID rows and reports the count of excluded WARNING rows; unsupported monetary bases or mixed currencies return unavailable. JSON download and the narrow deterministic question re-fetch and reauthorize the selected batch; they share calculation and source references. The calculation is not revenue, expenditure, net income or cash flow. No model is called. No authoritative financial publication is allowed.

The access code, batch and file changes clear displayed results. The page rechecks access before report download and answers; displayed results are cleared on window blur or after 15 seconds. This is bounded client staleness, not immediate revocation notification. The local gate checks development mode, the Vercel flag, loopback request host/origin and the synthetic capability; it does not attest the network peer, so binding the server to loopback is mandatory. The sample identity is not an identity provider or real organization membership. Native PostgreSQL concurrency and production role enforcement remain unverified. Never use this endpoint for real data or deploy it as a production financial API.
