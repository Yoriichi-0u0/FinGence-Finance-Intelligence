# Local scoped source-amount calculation

`createScopedFinancialTools(deps).sumSourceAmounts(transactionIds, request, warningPolicy)` is an internal-only experiment. It accepts 1–50 unique transaction UUIDs, performs an independently authorized and durably audited P2 detail read for each, and returns no partial financial result if any read fails. It accepts only one batch, the `source_signed_amount` basis and a common source-provided currency. It rejects debit/credit, inferred/default currency, mixed currencies and cross-batch selections rather than inventing an accounting convention. It uses the existing exact decimal helper, preserves source transaction/batch/row identifiers and requires explicit WARNING inclusion or exclusion.

The result is a sum of selected source literals, not revenue, expenditure, cash flow, a dataset-wide total or a reconciliation result. A selection containing only excluded warnings is unavailable, not zero. This is not connected to a model, report, frontend, HTTP route or production database.

The current P2 interface performs separate reads; this tool does not provide a shared atomic tenant/authorization snapshot or production identity/ownership. One-batch restriction and per-read authorization reduce scope but do not establish transaction-level consistency under concurrent session, membership or ownership changes. Production use requires a reviewed same-tenant snapshot, durable auditing semantics, real identity/ownership, and policy authorization. Tests use only disposable PGlite and synthetic sessions; they do not establish native PostgreSQL behavior.
