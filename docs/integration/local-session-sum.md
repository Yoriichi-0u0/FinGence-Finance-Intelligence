# Local synthetic session and source-amount sum

This server-only experiment reads existing grouped-persistence financial records under a synthetic, database-resolved session and batch owner. It exposes no HTTP route and is restricted to local development or test, never Vercel. `createLocalSessionSumService(database).sum(token, recordIds, warningPolicy)` accepts one to 50 UUIDs and returns `DENIED`, `UNAVAILABLE`, or an exact-decimal `SOURCE_SIGNED_AMOUNT_SUM` with currency and row references. It is an algebraic source-value sum, not revenue, expenditure, cash flow, or an accounting interpretation. Mixed batches, unsupported monetary or currency bases, and missing records do not produce a sum.

The test-only schema and token provisioning live in `tests/fixtures/local-session-scope.sql` and the integration test. The service hashes a high-entropy opaque session token, resolves its membership and organization in the database, restricts this calculation to active Finance memberships, locks the session, membership, financial rows and ownership rows, rechecks the session and ownership, and commits a content-free audit in the same transaction before returning values. Other finalized roles are denied for this operation; this is not a complete capability matrix. There is no automatic retry.

This experiment does **not** implement an identity provider, session issuance, a trusted production membership lifecycle, or atomic tenant assignment during grouped persistence. Test-created ownership rows are fixtures, not evidence of a secure production writer. The existing V2 verified document batch and publication policy are not connected to this service; no V2 results are cast to C1. It does not provide authenticated HTTP access, reports, chatbot, reconciliation or forecasting. The fixture SQL is not a production migration. PGlite checks cannot establish native PostgreSQL concurrent lock behavior; verify that separately with disposable native PostgreSQL before considering production integration.

`createLocalFinancialReportService` composes the authorized sum into a JSON report and an explicitly `DETERMINISTIC_ONLY` answer object sharing the exact value and references. This is a programmatic local artifact, not a downloadable browser report, a natural-language chatbot, a claim that an AI model ran, or an authoritative financial result. It withholds both artifacts if authorization or durable audit fails.
