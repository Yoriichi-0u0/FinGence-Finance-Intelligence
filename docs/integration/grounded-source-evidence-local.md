# Local scoped evidence for a future grounded assistant

This server-only module adds a narrow claim-verification building block. It uses the existing P2 `createScopedReadService` for each transaction, so trusted principal, active membership, database-resolved scope and durable audit must be supplied by the caller. Missing real application identity/membership and ownership remain unresolved; the test fixture is not runtime authentication. No HTTP endpoint or model dispatch is added.

`createGroundedEvidenceService(deps).retrieve(id, request)` returns an allowlisted subset of one authorized persisted transaction with actual batch and source-row references. `verify(id, request, proposal)` performs a fresh scoped read and accepts only nonempty, unique field/value claims matching exact source strings. The allowed fields are transaction date, posting date, reference, source amount, debit, credit and currency. Arbitrary prose, unsupported fields, invented amounts and duplicate claims fail. Monetary basis and warning status accompany results; this helper does not infer cash flow, revenue, expense or ledger-net meanings. Exact string matching is not a verifier for arbitrary natural-language claims or a substitute for a complete grounded chatbot.

Tests use actual synthetic ingestion, grouped persistence, PGlite, P2 scoped reads and protected audit. They do not establish real user authentication, native PostgreSQL concurrency, a model response, a complete chatbot or authorization to send data to an external provider. No provider integration or production route exists in this slice.
